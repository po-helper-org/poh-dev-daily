# 0001. Дейлик через агента: один скилл, Jira через mcp-atlassian, запись после «да»

Статус: принято, 2026-10-06

## Контекст

Разработчики тратят время на дейлик и на поддержание Jira в актуальном виде. Нужен короткий и простой скилл: разработчик рассказывает своему Claude Code, что сделал и что мешает, а агент выравнивает задачи, пишет статусы и комментарии и помогает спланировать день.

## Решения

1. **Плагин Claude Code с одним скиллом `daily`, вызываемым моделью.** Срабатывает на естественную фразу («дейлик», «что у меня по задачам»), поэтому разработчику не нужно помнить команду. Плагин, а не голый `SKILL.md`, — потому что вместе со скиллом надо поставить MCP-сервер Jira и спросить токен. Установка — две команды из этого же репозитория, он служит маркетплейсом.

2. **Jira — [`mcp-atlassian`](https://github.com/sooperset/mcp-atlassian) через `uvx`, версия закреплена (0.23.1).** Это стандартный MCP для Server/Data Center с Personal Access Token, своего кода поддерживать не нужно. Версия закреплена, чтобы обновление пакета не меняло поведение молча. Токен — `userConfig` с `sensitive: true`: лежит в защищённом хранилище, в MCP-сервер подставляется через `${user_config.jira_token}`.
   *Отвергнуто:* свой скрипт поверх REST (больше кода, а выигрыша нет); операции через общего серверного агента команды (это не собственный Claude разработчика).

3. **Наименьшие права: белый список `ENABLED_TOOLS`.** Читать (включая панель разработки — MR без `glab`), переводить и комментировать. `TOOLSETS=all` нужен, чтобы панель разработки (не входит в набор по умолчанию) прошла фильтр; пересечение с белым списком оставляет только перечисленное. Создание, правка полей, удаление и worklog закрыты на уровне сервера, а не только инструкцией. Так ошибка модели не может стоить больше, чем лишний комментарий или переход, а их видно и легко откатить.

4. **План правок → одно «да» → применение.** Ошибочный переход в Jira видит вся команда. Подтверждение стоит разработчику одно слово, при этом он видит каждую правку до записи. Если согласие дано заранее («применяй сразу»), шаг подтверждения пропускается.

5. **Сверка трёх источников: рассказ ↔ Jira ↔ git.** Коммиты подтверждают слова или противоречат им. Факт без следов («MR смержен на сервере») не отбрасывается, а помечается «со слов». Сам git статус не меняет — так скилл не становится автоматом, который двигает задачи по коммитам.

6. **Дневник в `${CLAUDE_PLUGIN_DATA}`, а не в репозитории.** Личный, общий для всех проектов разработчика, в git проекта не попадает. Вчерашний «План» становится сегодняшними обещаниями, и так появляются хвосты. Минус: при удалении плагина дневник удаляется (`--keep-data` его сохраняет).

7. **Первый запуск без анкеты.** Первый дейлик сразу идёт на умолчаниях (текущий репозиторий, 10–19, все проекты). Профиль записывается с ними, а разработчик правит его одной фразой. Вопросов сверки — не больше трёх.

8. **Без worklog и календаря в первой версии.** Списание времени не выбрано в требованиях. Календаря у разработчиков нет в общем доступе через MCP, поэтому встречи агент берёт из рассказа.

9. **Права на запись дневника.** `allowed-tools` скилла действует только в ходе, где скилл вызван. Поэтому профиль и черновик дневника пишутся до вопроса «да?», а итоговая правка дневника после «да» может спросить разрешение. README даёт постоянное правило для `~/.claude/settings.json`.

## Последствия

- Скилл работает с любым Jira MCP, у которого те же имена инструментов `jira_*`.
- У команд разный workflow. Переходы всегда берутся из `jira_get_transitions`, чтобы не угадывать статус.
- Проверка поведения — `claude plugin eval` с подменной Jira (`evals/`). Реальная Jira в тестах не нужна.
