# Дейлик через агента

Разработчик выгружает свободный рассказ. Твоя работа — **сверка**: рассказ + Jira + git → **план правок** → после «да» правки в Jira → план дня и сводка для команды. Всё фиксируется в **дневнике**.

Рабочие файлы (личные, вне репозиториев):
- профиль — `${CLAUDE_PLUGIN_DATA}/profile.md`
- дневник — `${CLAUDE_PLUGIN_DATA}/journal/ГГГГ-ММ-ДД.md`, файл на день, формат — в конце

Jira — инструменты `jira_*` плагина. Их нет или они отвечают ошибкой доступа — [troubleshooting.md](troubleshooting.md).

## Шаги

### 1. Контекст

Прочитай профиль. Нет файла — первый запуск: запиши профиль с умолчаниями по [setup.md](setup.md).
Найди в `journal/` последний файл до сегодняшнего: его «План» и «Блокеры» — **обещания**, которые сегодня сверяются.
Готово, когда: профиль есть, обещания выписаны (или отмечено «дневника нет»).

### 2. Факты из Jira

`jira_search` с `fields: "summary,status,updated,priority,issuetype"`, `limit: 50`:
- открытые мои: `assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC`
- закрытые со вчера: `assignee = currentUser() AND statusCategory = Done AND updated >= startOfDay(-1d)`

«Вчера» — прошлый рабочий день: в понедельник это пятница, `startOfDay(-3d)`. В профиле заданы проекты — добавь `AND project in (…)`.
Задачи из рассказа и обещаний, которых нет в выборке, открой `jira_get_issue` по ключу.
Готово, когда: у каждой задачи из рассказа, обещаний и выборки есть статус и дата обновления.

### 3. Доказательства из git

Для каждого репозитория из профиля — отдельными командами:

```bash
git -C <repo> config user.email
git -C <repo> log --all --since="<прошлый рабочий день> 00:00" --author="<email>" --pretty='%h %ad %s' --date=short
git -C <repo> branch --show-current
```

Ключи задач (`[A-Z][A-Z0-9]+-\d+`) бери из сообщений коммитов и имён веток. MR: при `glab: да` — `glab mr list --author=@me` в каждом репозитории; иначе — `jira_get_issue_development_info` по задачам из рассказа, которые сдвинулись (панель разработки Jira, если она связана с GitLab).
Доказательство подтверждает рассказ или противоречит ему; само по себе статус не меняет. Факт без следов (MR смержен, договорённость) остаётся в силе с пометкой **«со слов»**.
Готово, когда: каждому ключу сопоставлены коммиты/MR или «нет следов».

### 4. Сверка

По каждой задаче: рассказ ↔ Jira ↔ git → действие. Совпадает и нового нет — задача уходит в строку «без изменений: …», туда же задачи в To Do, о которых рассказ молчит.

**Переход статуса** — рассказ говорит, что задача ушла дальше статуса в Jira. Вызови `jira_get_transitions` и возьми целевой статус из ответа по словам разработчика:

| Разработчик говорит | Целевой статус |
|---|---|
| «открыл MR», «отдал на ревью» | статус ревью |
| «доделал», «смержил» | тестирование, если есть в переходах, иначе готово |
| «проверили», «выкатили», «закрыл» | готово |
| «блокер», «стоит», «жду» | остаётся как есть, факт — в комментарий; статус «Заблокирована» — когда разработчик назвал его сам |

Целевой статус ставь сам по таблице: разработчик увидит план и поправит одной фразой.

**Комментарий** — факт, которого Jira не знает: блокер и от кого ждём, договорённость, ссылка на MR, причина задержки. Ожидание, видное по статусу (Code Review ждёт ревьюера), уже известно Jira. Переходу хватает самого перехода.

**Хвосты** — то, что рассказ не объясняет:
- обещание из вчерашнего плана, о котором рассказ молчит;
- вчерашний блокер, о котором рассказ молчит (снят или всё ещё ждём?);
- задача «в работе» без обновлений 3+ рабочих дня, о которой рассказ молчит;
- работа из рассказа без ключа Jira;
- рассказ и git расходятся (сказал «доделал» — коммитов нет; есть коммиты — задача в To Do).

Хвост с очевидным ответом становится действием (переход, комментарий или перенос в план дня), остальные — вопросами: не больше трёх, у каждого вариант по умолчанию — «PAY-98 ещё в работе? (по умолчанию: оставляю как есть)».
Готово, когда: каждая задача, обещание и хвост закрыты действием, вопросом или строкой «без изменений».

### 5. План дня (черновик)

Пожелания разработчика («до обеда в фокусе», «PAY-103 сегодня не трогаю») важнее правил ниже.

- **Результаты дня** — 1–3 задачи, которые разработчик сам сдвинет сегодня, с ключами; порядок «ближе к Done — раньше»: правки по ревью и ответы тестированию, потом новое. Задачи, ждущие других, — строкой «на контроле».
- **Новая работа** — из To Do по приоритету, если лимит позволяет.
- **Лимит:** не больше двух активных задач одновременно; ждущие (ревью у другого, тестирование, блокер) не считаются.
- **Встречи** из рассказа — фиксированные блоки; без длительности — 1 час. Фокус-работу ставь в самое длинное свободное окно.
- **Чужие ревью** — утром, если о них известно из рассказа или `glab mr list --reviewer=@me`.
- **Запас** ~25% рабочего времени без обеда — на прерывания. Рабочий день и обед — из профиля.

Готово, когда: каждый час рабочего дня занят блоком (задача, встреча, обед, запас).

### 6. План правок → «да»

Запиши дневник за сегодня: правки — с пометкой «предложено», план — с пометкой «черновик». Затем одно сообщение разработчику:

```
Сверка за пн 05.10 · в работе: 3

Правки в Jira (применю после «да»):
1. PAY-101  В работе → Тестирование   — «доделал»: коммиты 05.10; MR смержен (со слов)
2. PAY-98   комментарий: «Блокер: жду доступ к стенду от DevOps (запрос от 02.10)»
Без изменений: PAY-102 (ревью), PAY-103 (To Do)

Вопросы:
1. PAY-104 вчера была в плане — начал? (по умолчанию: не начата)

План дня (черновик):
10:00–10:30 PAY-102 правки по ревью
10:30–13:00 PAY-103 фокус
13:00–14:00 обед
14:00–15:00 созвон с аналитиком
…
На контроле: PAY-101 (тестирование), PAY-98 (блокер)
```

«В работе» — задачи с `statusCategory = In Progress`. Первый запуск — добавь строку профиля из [setup.md](setup.md).

Пиши в Jira после явного согласия: «да», «ок», «применяй» в ответе — или если исходное сообщение прямо разрешает применять без подтверждения («применяй сразу»; тогда это сообщение не отправляется, его строки уходят в итог шага 8). Ответ с поправками → перестрой план и покажи заново. Ответ на вопросы вместе с «да» → применяй с учётом ответов. Правок и вопросов нет — сразу шаг 8.
Готово, когда: дневник записан и есть согласие (или правки отменены разработчиком).

### 7. Применение

- **Переход:** `jira_transition_issue` с `issue_key` и `transition_id` = `id` перехода из шага 4. В нужный статус прямого перехода нет — оставь задачу как есть и назови в отчёте доступные переходы.
- **Комментарий:** `jira_add_comment` с `issue_key` и `body` — 1–3 строки по-русски от первого лица разработчика, только факты и ссылки:
  `Блокер: жду доступ к стенду от DevOps (запрос от <дата>). Без него не проверить интеграцию.`
  `MR: <ссылка>. Осталось: ревью.`
- Каждая операция → строка отчёта: `✓ PAY-101 → Тестирование` или `❌ PAY-98 комментарий: <ошибка>`. Ошибку в своих аргументах исправь и повтори вызов; ответ Jira с ошибкой (403, нет перехода) сразу идёт в отчёт. Остальные операции выполняй в любом случае.

Готово, когда: у каждой правки из плана есть строка ✓ или ❌.

### 8. Итог

Обнови дневник: «Правки в Jira» — по факту (✓/❌), «План» — итоговый, без пометки «черновик». Затем одно сообщение:
1. отчёт по операциям;
2. итоговый план дня;
3. сводка для чата команды — три строки с ключами:
   ```
   Сделал: PAY-101 сохранение карты → тестирование, PAY-95 закрыта
   Сегодня: PAY-102 правки по ревью, PAY-103 начинаю
   Блокер: PAY-98 жду доступ к стенду от DevOps
   ```
   «Сделал» — задачи, которые сдвинулись со вчера, включая закрытые. Блокеров нет — `Блокер: нет`;
4. путь к файлу дневника.

Готово, когда: дневник совпадает с отправленным итогом.

## Дневник

```markdown
# 2026-10-06
## Рассказ
<сжато, своими словами>
## Правки в Jira
- ✓ PAY-101 → Тестирование
- предложено: комментарий в PAY-98
## План (черновик)
- PAY-102 правки по ревью
- PAY-103 начать
## На контроле
- PAY-101 тестирование
## Блокеры
- PAY-98 доступ к стенду (DevOps)
```

«План» и «Блокеры» завтра станут обещаниями (шаг 1), черновой план — тоже. На шаге 8 «(черновик)» из заголовка убирается. Повторный дейлик в тот же день дописывает файл.
