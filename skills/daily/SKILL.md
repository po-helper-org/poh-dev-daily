# Дейлик через агента

Разработчик выгружает свободный рассказ. Твоя работа — **сверка**: рассказ + Jira + git → **план правок** → после «да» правки в Jira → план дня → сводка для команды. Всё фиксируется в **дневнике**. Разработчик тратит 2–3 минуты и одно подтверждение.

Рабочие файлы (личные, вне репозиториев):
- профиль — `${CLAUDE_PLUGIN_DATA}/profile.md`
- дневник — `${CLAUDE_PLUGIN_DATA}/journal/ГГГГ-ММ-ДД.md`, файл на день

Jira — инструменты `jira_*` (MCP-сервер плагина `jira` или любой Jira MCP с теми же именами). Инструментов нет или они отвечают ошибкой — [troubleshooting.md](troubleshooting.md).

## Шаги

### 1. Контекст

Прочитай профиль. Нет файла — первый запуск: запиши профиль с умолчаниями по [setup.md](setup.md) и продолжай.
Найди в `journal/` последний файл до сегодняшнего: его раздел «План» — **обещания**, которые сегодня сверяются.
Готово, когда: профиль есть, обещания выписаны (или отмечено «дневника нет»).

### 2. Факты из Jira

`jira_search` с `fields: "summary,status,updated,priority,issuetype"`, `limit: 50`:
- открытые мои: `assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC`
- закрытые со вчера: `assignee = currentUser() AND statusCategory = Done AND updated >= startOfDay(-1d)`

«Вчера» — прошлый рабочий день: в понедельник это пятница, `startOfDay(-3d)`. В профиле заданы проекты — добавь `AND project in (…)`.
Задачи из рассказа и обещаний, которых нет в выборке, открой `jira_get_issue` по ключу.
Готово, когда: у каждой задачи из рассказа, обещаний и выборки есть статус и дата обновления.

### 3. Доказательства из git

Для каждого репозитория из профиля — отдельными командами:

```bash
git -C <repo> config user.email
git -C <repo> log --all --since="<прошлый рабочий день> 00:00" --author="<email>" --pretty='%h %ad %s' --date=short
git -C <repo> branch --show-current
```

`glab: да` — ещё `glab mr list --author=@me` в каждом репозитории. Ключи задач (`[A-Z][A-Z0-9]+-\d+`) бери из сообщений коммитов и имён веток.
Доказательство подтверждает рассказ или противоречит ему; само по себе статус не меняет. Факт без следов (MR смержен на сервере, договорённость) остаётся в силе с пометкой **«со слов»**.
Готово, когда: каждому ключу сопоставлены коммиты/MR или «нет следов».

### 4. Сверка

По каждой задаче: рассказ ↔ Jira ↔ git → действие. Совпадает и нового нет — задача уходит в строку «без изменений: …». Задачи в To Do, о которых рассказ молчит, — тоже «без изменений»: из них шаг 7 берёт новую работу.

Действия — двух видов.

**Переход статуса** — рассказ говорит, что задача ушла дальше статуса в Jira. Вызови `jira_get_transitions` и возьми целевой статус из ответа по словам разработчика:

| Разработчик говорит | Целевой статус |
|---|---|
| «открыл MR», «отдал на ревью» | статус ревью |
| «доделал», «смержил» | тестирование, если есть в переходах, иначе готово |
| «проверили», «выкатили», «закрыл» | готово |
| «блокер», «стоит», «жду» | перехода нет — это комментарий; статус «Заблокирована» — только если разработчик сам его назвал |

Сомнение в целевом статусе вопросом не становится: разработчик видит план и поправит одной фразой.

**Комментарий** — факт, которого Jira не знает: блокер и от кого ждём, договорённость, ссылка на MR, причина задержки. Ожидание, видное по статусу (задача в Code Review ждёт ревьюера), — не новый факт. Переход без нового факта комментария не требует.

**Хвосты** — то, что рассказ не объясняет:
- обещание из вчерашнего плана, о котором рассказ молчит;
- вчерашний блокер, о котором рассказ молчит (снят или всё ещё ждём?);
- задача «в работе» без обновлений 3+ рабочих дня, о которой рассказ молчит;
- работа из рассказа без ключа Jira;
- рассказ и git расходятся (сказал «доделал» — коммитов нет; есть коммиты — задача в To Do).

Хвост с очевидным ответом становится действием (переход, комментарий или перенос в план дня), остальные — вопросами. Вопросов не больше трёх, у каждого вариант по умолчанию: «PAY-98 ещё в работе? (по умолчанию: оставляю как есть)».
Готово, когда: каждая задача, обещание и хвост закрыты действием, вопросом или строкой «без изменений».

### 5. План правок → «да»

Составь черновик плана дня (шаг 7) и запиши черновик дневника (шаг 9, правки — с пометкой «предложено»). Покажи план правок, вопросы и черновик плана дня одним сообщением (формат — ниже) и жди ответа. На первом запуске добавь строку `Профиль: <репозитории>, <рабочий день>, проекты: все — поправь, если не так`.

Пиши в Jira только после явного согласия: «да», «ок», «применяй» — или если исходное сообщение уже говорит «применяй сразу». Ответ с поправками → перестрой план и покажи заново. Ответ на вопросы вместе с «да» → применяй с учётом ответов. Правок нет и вопросов нет — сразу шаги 7–9.

### 6. Применение

- **Переход:** `jira_transition_issue` с `issue_key` и `transition_id` = `id` перехода из шага 4. Прямого перехода в нужный статус нет — не проходи цепочку сам: оставь задачу, в отчёте назови доступные переходы.
- **Комментарий:** `jira_add_comment` с `issue_key` и `body` — 1–3 строки по-русски от первого лица разработчика, факты и ссылки, без вступлений и подписей:
  `Блокер: жду доступ к стенду от DevOps (запрос от <дата>). Без него не проверить интеграцию.`
  `MR: <ссылка>. Осталось: ревью.`
- Каждая операция → строка отчёта: `✓ PAY-101 → Тестирование` или `❌ PAY-98 комментарий: <ошибка>`. Ошибку в своих аргументах исправь и повтори; ошибку Jira не повторяй. Ошибка одной операции не останавливает остальные.

Инструменты `jira_*` в этом скилле — только чтение, переход и комментарий. Поля, исполнители, новые задачи и списание времени — забота разработчика: попросил — предложи сделать в Jira руками.

### 7. План дня

Пожелания разработчика («до обеда в фокусе», «PAY-103 сегодня не трогаю») важнее правил ниже.

- **Результаты дня** — 1–3 задачи, которые разработчик сам сдвинет сегодня, с ключами; порядок «ближе к Done — раньше»: правки по ревью и ответы тестированию, потом новое. Задачи, ждущие других, — одной строкой «на контроле».
- **Новая работа** — из To Do по приоритету, если лимит позволяет.
- **Лимит:** не больше двух активных задач одновременно; ждущие (ревью у другого, тестирование, блокер) не считаются.
- **Встречи** из рассказа — фиксированные блоки; без длительности — 1 час. Фокус-работу ставь в самое длинное свободное окно.
- **Чужие ревью** — утром. Источник — рассказ и, при `glab: да`, `glab mr list --reviewer=@me`; нет ни того, ни другого — слота нет.
- **Запас** ~25% рабочего времени без обеда — на прерывания. Рабочий день и обед — из профиля.

### 8. Сводка для команды

После применения правок (или сразу, если правок нет) — три строки для чата команды, с ключами:

```
Сделал: PAY-101 сохранение карты → тестирование, PAY-95 закрыта
Сегодня: PAY-102 правки по ревью, PAY-103 начинаю
Блокер: PAY-98 жду доступ к стенду от DevOps
```

«Сделал» — задачи, которые сдвинулись со вчера, включая закрытые. Блокеров нет — `Блокер: нет`.

### 9. Дневник

`journal/<сегодня>.md` — пишется на шаге 5, после применения обнови «Правки в Jira» и «План»:

```markdown
# 2026-10-06
## Рассказ
<сжато, своими словами>
## Правки в Jira
- ✓ PAY-101 → Тестирование
- предложено: комментарий в PAY-98
## План
- PAY-102 правки по ревью
- PAY-103 начать
## Блокеры
- PAY-98 доступ к стенду (DevOps)
```

Раздел «План» завтра станет обещаниями (шаг 1). Повторный дейлик в тот же день дописывает файл.

## Формат ответа

На шаге 5:

```
Сверка за пн 05.10 · в работе: 3

Правки в Jira (применю после «да»):
1. PAY-101  В работе → Тестирование   — «доделал»: коммиты 05.10; MR смержен (со слов)
2. PAY-98   комментарий: «Блокер: жду доступ к стенду от DevOps (запрос от 02.10)»
Без изменений: PAY-102 (ревью), PAY-103 (To Do)

Вопросы:
1. PAY-104 вчера была в плане — начал? (по умолчанию: не начата)

План дня (черновик):
10:00–10:30 PAY-102 правки по ревью
10:30–13:00 PAY-103 фокус
13:00–14:00 обед
14:00–15:00 созвон с аналитиком
…
На контроле: PAY-101 (тестирование), PAY-98 (блокер)
```

«В работе» — задачи с `statusCategory = In Progress`.

После применения: отчёт по операциям, итоговый план дня, сводка для команды, путь к файлу дневника. Согласие было дано заранее — это одно сообщение, а в его начало идут строка сверки, «Без изменений» и строка профиля первого запуска.
