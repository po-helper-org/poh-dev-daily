# Когда Jira недоступна

Дейлик без Jira — план дня и сводка по рассказу с пометкой «Jira не сверена»; статусы берутся только из ответов Jira. Разработчику — одна причина и одно действие из таблицы.

| Признак | Причина | Что сказать разработчику |
|---|---|---|
| Инструментов `jira_*` нет, в `/mcp` сервер `plugin:dev-daily:jira` — failed | Не заданы адрес/токен или нет `uv` | `/plugin` → dev-daily → Configure: адрес и токен; `uv` ставится `brew install uv`; затем перезапуск Claude Code |
| 401 / Unauthorized | Токен истёк или отозван | Выпустить новый Personal Access Token в профиле Jira, ввести в Configure |
| `CERTIFICATE_VERIFY_FAILED`, SSL | Jira на корпоративном сертификате | Добавить в `~/.zshrc` строку `export REQUESTS_CA_BUNDLE=<путь к корневому сертификату .pem>` и перезапустить Claude Code из нового терминала; запасной вариант — выключить «Проверять SSL-сертификат Jira» в Configure |
| Таймаут, `Connection refused`, ошибка DNS | Jira доступна только из корпоративной сети | Включить VPN и повторить |
| `uvx` не скачивает пакет | Нет доступа к PyPI | Настроить прокси или зеркало PyPI (`UV_INDEX_URL`) и перезапустить Claude Code |
